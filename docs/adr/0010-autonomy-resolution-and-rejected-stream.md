# 0010. 유효 자율 수준은 "가장 좁은 선언이 수준, 가장 넓은 선언이 상한"이며 거부는 별도 스트림에 남는다
Status: accepted · Date: 2026-09-10
## Context
스펙 §4.1은 제약은 넓은 우선, 컨텍스트는 좁은 우선이라고만 말한다. 한 범위에 적용되는 자율 선언이 여럿일 때(조직·제품·팀·리포) 유효 수준을 하나로 정하는 규칙이 코드에 필요했다. 또 §3.6c의 `Rejected` 이벤트를 어느 스트림에 쓸지 정해야 했다: 애그리게이트 스트림에 쓰면 버전이 오르고 낙관적 동시성이 흔들린다.
## Decision
- 유효 **수준** = 대상에 적용되는 선언 중 **가장 좁은** 범위의 수준(컨텍스트 규칙: 하위가 구체화). 선언이 없으면 L0.
- 유효 **상한** = 적용되는 모든 선언의 상한 중 **최소**(제약 규칙: 상위가 구속). 수준은 상한을 넘지 못한다.
- 같은 폭의 범위끼리는 canonical 문자열 순(제품이 팀보다 앞)으로 결정적으로 정렬한다.
- `Rejected`는 전역 스트림 `rejected`에 append한다. 애그리게이트 버전은 손대지 않고, 거부는 사라지지 않는다.
- Gate의 멱등 ID는 `(actor, proposal_ref)`의 해시로 앱이 파생한다. 같은 제안을 다시 물으면 같은 gate가 돌아온다.
## Consequences
팀이 L2를 선언해도 제품 상한이 L1이면 L1이다. 다른 팀 범위의 선언은 대상에 적용되지 않는다. 거부 이력은 `rejected` 스트림 하나를 읽으면 전부 보인다. 소유 지도(9주차)가 생기면 `DecideContext.Judges`가 채워져 타 팀 소유 닻의 settle·gate 규칙이 활성화된다.
